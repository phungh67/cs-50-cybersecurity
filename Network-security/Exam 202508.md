Firewall is exclusively operating at layer 3 and 4 - **False** since except layer 1 - firewall can be deployed in all layers.

>[! Question]
>Scanning network is one of the first step in both defense and attack. Hence, there are several scanning techniques to use. On the other hand, there are two types of transport protocol (main): `TCP` and `UDP`. With these two, how message "ICMP port unreachable" could be understood?

- With `UDP`, unreachable means port is closed. (But no message can not be determined if the port is opened or filtered by the firewall).
- With `TCP`, unreachable means port is protected by a firewall. Normally, the scan should return `RST` or silent.

>[! Question]
>The methodology of OS fingerprinting - some `TCP` example? Any possbile way for a main border firewall can mitigate this?

The OS fingerprint can be done with a `TCP` scan, by combination several techniques and flags. For example, a `FIN` scan can detect the system is Window of Linux (since Windown will return `RST` upon receiving `FIN` packet, unlike Linux: sends `RST` for closed and none for opened). Also the `NULL` and `Xmas` scans are famous for using several flags or no flag at all to inspect the implementation of the network stack, and based on the response, some information about the window size, time to live and maximum segment size can be used to know the OS.

A firewall can block reply `ICMP` message to prevent the attacker gain information, or also can modify the response ...

>Maginfication attacks (Smurf and Fraggle), the traffic sent by the adversary is maginified several times when received by the victim. Describe one maginfication strategy using `ICMP` and another strategy making use of `DNS`. Explain what was sent by the adversary, how the traffic is maginified and what is receieved by the victim.

**Smurf**: attacker forged an `IMCP` message with the victim's IP address then sent it the to broadcast address of the network. >[! Question]
>What caused Linux systems to crash during a Teardrop attack with overlapping fragments?

In Teardrop attack, the attacker sent a normal fragment first, then the second fragment that was fit perfectly within the first one. So that when the system tried to reassemble it, the math calculation would be look like:
$$
byte\_to\_write = end\_of\_second - end\_of\_first
$$
Since the second sits perfectly inside the first one, the result of this will be negative, triggering the unsigned integer bug, producing a very large positive number, causing bug.

>[! Question]
>Describe the mechanism of the Bonik attack?

An oversized IP datagram can be created with the fragment with an offset and length extending the datagram beyond its limit. For example, the offset was set to 65000 and length to 1000 bytes (so the whole datagram will be larger than normal). (65000 + 1000 bytes > 65535).

>[! Question]
>Stateful firewalls maintain both a state table and a rule table. Describe how these tables are used to handle incoming `UDP` packet with an example, in which the rule table contains at least one entry. Another example to describe how these tables are used to handle `TCP` packets.

Firewall checks the state table first, if the incoming packet belongs to an existing session, bypass the rule table and accepts it. IF not, check the rule table, if in the rule table contains at least one rule that match with the packet's parameters (source, destination, port,...), accepts it and create an entry in the rule table to track the said connection.

With `UDP`, since it does not have any states, a pseudo state will be created "time out".

With `TCP`, firewall traces the three-way handshake state, from `SYN`, `SYN/ACK` and `ACK` to `ESTABLISHED`

>[! Question]
>MAC flooding can cause problem for switches. Why, what could the possbile again for this attack. How to configure the switch in this case.

More intelligent switches can learn where hosts (MAC addresses) are located and will normally not forward private traffic between two ports to any other ports. The attacker’s goal is to overflow the switch memory with garbage MAC addresses to make it forget the real MAC addresses and force it to broadcast all traffic to all ports which enables the attacker to listen to all ongoing conversations.
(This can be detected by some switches, for example by limiting number of MAC
addresses per port and/or to lock some MAC addresses to certain ports.)
