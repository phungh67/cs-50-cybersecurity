# 3. Firewall and `TLS`

Firewall is exclusively operating at layer 3 and 4 - **False** since except layer 1 - firewall can be deployed in all layers.

`Stateful` firewalls are typically more vulnerable to SYN flood attacks than `stateless` ones. - **True** since it can exhaust the firewall, cause the state table.

`NAT` devices do not affect `TCP` or `UDP` port number - **False** the natural of `NAT` is to change the port and the source IP addresses before sending these packets to other destinations (even unpack and repack again).

`NAT` gateways are preferred compared to stateless firewalls because they can inspect
packet content - **False** even `NAT` can sometime be used as a firewall, but it cannot inspect the packet content as the firewall and also, `stateless` firewall does not have the ability to inspect.

Forward secrecy in TLS can be achieved using ephemeral Diffie-Hellman key exchanges - **True** - the way that only shared information was exposed and each session, 2 parities separately decided on its own secret but still end up in the same session key.

In `TLS` 1.2, the client can send a certificate to the server in the `client_hello` message to authenticate itself - **False** the hello use to request the server's certificate and most importantly, decide the cipher, and key exchange algorithms.

`TLS` can mitigate the effects of `TCP` session hijacking by encrypting and authenticating application data. - **True** since the nature of the encryption in the communication link is to avoid man-in-the-middle hijacking.

In the Heartbleed attack, an attacker can retrieve private keys, passwords, and other
sensitive data from a server's memory - since it said that this type of attack aim to mess around with the header? **True** - abuse the header, specified a massive chunk of data but only pass a small payload, the server will echo back some data "next to" the payload and hence probably reveal the secret.

>What is the purpose of the Ticket Granting Ticket for the user in the `Kerberos` system?

To allow the user to access the Ticket Granting System, in which the user's request to access specific service can be made, and if it is legally, a ticket will be granted.

To restrict the user's access to critical systems/services. Since the `VPN` allowing restrict `IP` based on an allowance pool.

[[Port knocking]]

At least 2048 bits

First, `TLS` still has many fatal bugs, second, they support less protocol than the `IPSec`

Asset-level protection (since the principle is: treat any traffic is un-trusted)

To ensure data integrity by generating fixed-length, one-way output (check the signature and if the data was not tampered, the hashed was generated based on the content of the message itself).

To ensure incoming and outgoing traffic uses valid IP addresses
